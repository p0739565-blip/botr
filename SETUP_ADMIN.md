# Подключение админ-панели — пошаговая инструкция

Админка НЕ отдельный сервис — она встроена в тот же процесс, что уже
слушает `vpnapi.service`, и доступна по адресу:

    https://ваш-домен/admin/login

Отдельно перезапускать/настраивать ничего в Cloudflare-туннеле не нужно —
он уже проксирует весь трафик на этот же порт.

---

## 1. Скопировать файлы на VPS

На вашей VPS проект лежит в `/opt/vpn-bot`. Из этого архива нужно
перенести на сервер **весь `app/`** и обновлённый `requirements.txt`,
подменив старые версии файлов.

Проще всего через `scp` с вашего компьютера (архив уже распакован
в папку `vpnbor2/`):

```bash
scp -r vpnbor2/app root@ВАШ_IP:/opt/vpn-bot/
scp vpnbor2/requirements.txt root@ВАШ_IP:/opt/vpn-bot/
```

Либо загрузите архив на сервер (`scp admin-panel.zip root@ВАШ_IP:~/`)
и распакуйте прямо там:

```bash
ssh root@ВАШ_IP
cd ~
unzip admin-panel.zip
cp -r vpnbor2/app/* /opt/vpn-bot/app/
cp vpnbor2/requirements.txt /opt/vpn-bot/requirements.txt
```

## 2. Поставить новые зависимости

Админке нужны 4 новых пакета — шаблоны, сессии, формы, хэширование
паролей:

```bash
cd /opt/vpn-bot
source .venv/bin/activate
pip install -r requirements.txt
```

Если venv называется иначе — активируйте свой, команда установки та же.

## 3. (Опционально) секрет для сессий

Ничего добавлять в `.env` НЕ обязательно — если `ADMIN_SESSION_SECRET`
не задан, он сгенерируется автоматически при первом запуске и
сохранится в `app/data/admin_session.key`. Дальнейшие рестарты бота
не будут разлогинивать админов.

Если всё же хотите задать его сами (например, чтобы он совпадал при
переносе на другой сервер) — добавьте в `.env`:

```env
ADMIN_SESSION_SECRET=любая-длинная-случайная-строка
```

## 4. Создать первого супер-админа

Это разовая операция — дальше всех остальных админов вы создаёте уже
через саму панель.

```bash
cd /opt/vpn-bot
.venv/bin/python -m app.admin.seed
```

Скрипт спросит логин и пароль (ввод пароля не отображается на экране —
это нормально). Он же сам создаст все новые таблицы в базе
(`admin_users`, `admin_permissions`, `audit_log`, `payments`), если их
там ещё нет — ничего вручную мигрировать не нужно.

## 5. Перезапустить сервисы

```bash
sudo systemctl restart vpnapi.service
sudo systemctl restart vpnbot.service
sudo systemctl status vpnapi.service --no-pager
journalctl -u vpnapi.service -n 30 --no-pager
```

`vpnbot.service` перезапускаем тоже — он теперь пишет платежи в новую
таблицу `payments` при оплате звёздами (обновлён `handlers/payment.py`).

Если в логах `vpnapi.service` нет traceback и статус `active (running)`
— всё поднялось. Заходите на `https://ваш-домен/admin/login`.

## Что внутри админки

### Роли
- **Супер-админ** — вы, всё включено: управление админами, все права.
- **Админ** — базовый набор (просмотр + ручная выдача/продление/отзыв
  подписки), настраивается вручную на уровне отдельных прав.
- **Наблюдатель** — только просмотр, ни одной кнопки действия. Права
  проверяются на сервере, а не только скрытием кнопок в интерфейсе —
  даже зная прямой URL, наблюдатель не сможет вызвать действие.

### Права — гранулярно
При создании/редактировании админа роль подставляет стартовый набор
галочек, но вы можете донастроить вручную под конкретного человека —
например, дать право продлевать подписки, но не выдавать доступ к
управлению другими админами.

### Разделы
- **Дашборд** — пользователи, активные подписки, продажи за
  день/неделю, оплаты звёздами.
- **Пользователи** — поиск, карточка пользователя с историей
  подписок и платежей, ручное продление (прибавляет дни к остатку,
  как и обычная оплата) и отзыв активной подписки.
- **Админы** (только супер-админ) — создание, редактирование прав,
  включение/выключение доступа. Обратите внимание: "удаление" админа
  на деле — деактивация (`is_active=False`), а не физическое удаление
  строки из базы. Сделано осознанно: так сохраняется история его
  действий в журнале аудита. Если админ деактивирован — зайти под ним
  больше нельзя, но кто что делал раньше — видно.
- **Журнал действий** (только супер-админ) — кто, когда и что изменил
  (выдал подписку, создал админа, поменял права и т.д.). Просмотры
  страниц не логируются — только изменяющие действия.

## Известные ограничения этой версии

- **Раздел "Платежи" отдельной страницей не сделан** — история оплат
  показывается внутри карточки конкретного пользователя. Общий список
  всех платежей по всем пользователям можно добавить отдельным шагом,
  если понадобится.
- **Управление тарифами и рассылки** — права (`MANAGE_TARIFFS`,
  `BROADCAST_MESSAGE`) в системе прав уже заложены и их можно выдавать
  админам, но самого функционала (страницы редактирования тарифов,
  формы рассылки) пока нет — это следующий шаг, если понадобится.
- **Оплата картой/криптой** — как и раньше, не реализована в самом
  боте (`NotImplementedError`), поэтому в истории платежей будут
  только записи по Stars.

## Если что-то пошло не так

Пришлите вывод:
```bash
journalctl -u vpnapi.service -n 50 --no-pager
```
и укажите, на каком именно шаге застряли — разберёмся.
