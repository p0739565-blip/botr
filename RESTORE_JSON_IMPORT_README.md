# Восстановление JSON-импорта + фикс сортировки (объединённый патч)

## Что случилось

Когда чинили сортировку серверов, я взял свежую версию `vless_links.py`
с GitHub как основу — а на GitHub к тому моменту уже не было ветки
JSON-импорта (она, похоже, потерялась при одном из ручных апдейтов
через "Add files via upload" — так до GitHub не долетело то, что
раньше накатывалось только напрямую на сервер через `scp`). Я это не
проверил и пересобрал файл только с фиксом сортировки. Когда вы
накатили его на VM — JSON-импорт вместе с ним пропал, поэтому форма
снова стала ругаться "это не ссылка-конфиг" на вставленный JSON.

## Что внутри этого архива

Все три файла собраны заново от текущего состояния GitHub-репозитория
и включают **обе** фичи сразу:

- `app/admin/config_json_import.py` — парсер JSON-конфига. Заодно
  поправил мелкий баг: при конфиге с ОДНИМ сервером (как ваш пример
  "🇵🇱 Польша (WiFi)") имя ссылки раньше могло получать лишний суффикс
  `— proxy`, потому что счётчик "один сервер или несколько" ошибочно
  учитывал служебные `freedom`/`blackhole` outbounds. Теперь считаются
  только реальные сервера.
- `app/admin/routes/vless_links.py` — и ветка `config_json` в
  `/admin/vless-links/new`, и сортировка `group.links` по `position`
  в `_groups_for()`.
- `app/admin/templates/vless_link_form.html` — переключатель
  «Ссылка / JSON-конфиг» на форме добавления.

## Как накатить

```bash
scp app/admin/config_json_import.py          user@your-vm:/opt/vpn-bot/app/admin/config_json_import.py
scp app/admin/routes/vless_links.py          user@your-vm:/opt/vpn-bot/app/admin/routes/vless_links.py
scp app/admin/templates/vless_link_form.html user@your-vm:/opt/vpn-bot/app/admin/templates/vless_link_form.html

sudo systemctl restart vpnapi.service
sudo systemctl status vpnapi.service --no-pager
```

Проверил парсер локально на вашем примере с Польшей (reality,
1 сервер) и на более раннем примере с балансером (3 сервера) — оба
разбираются корректно.

## Важное на будущее

Чтобы это не повторилось: GitHub у вас сейчас обновляется вручную
через drag-and-drop папки "app" (кнопка "Add files via upload") — если
в момент такой загрузки локальная копия на компьютере старее, чем то,
что реально стоит на VM, апдейт затирает более новые файлы на GitHub
старыми. После этого патча стоит либо руками аккуратно поддерживать
GitHub в актуальном состоянии, либо в следующий раз, когда будем
что-то чинить, явно проговорить — брать код с GitHub или сразу
спросить текущее состояние файлов с самой VM.
