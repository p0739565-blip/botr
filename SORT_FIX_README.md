# Хотфикс: не работала сортировка серверов внутри группы

## Что внутри

Замените этим файлом одноимённый в репозитории (путь совпадает со
структурой репо — просто распакуйте архив поверх `botr/`, подтвердив
перезапись):

- `app/admin/routes/vless_links.py`

## В чём была причина

Стрелочки "выше"/"ниже" у ссылки на самом деле честно меняли местами
`position` в БД (кнопка → `POST /admin/vless-links/{id}/move` →
`move_link` — с этой частью всё было в порядке).

Но список ссылок **внутри группы** на странице `/admin/vless-links`
рендерится через `group.links` — а у этой связи в
`app/models.py` (`VlessLinkGroup.links`) нет `order_by`. Поэтому
SQLAlchemy отдавала ссылки в произвольном порядке (фактически — по
ID), полностью игнорируя `position`. Получалось, что клик по стрелке
позицию в БД менял, а страница после перезагрузки показывала список
как будто ничего не произошло.

Ссылки **без группы** эту проблему не затрагивала — они выводятся
отдельным запросом `_ungrouped_links()`, в котором `order_by` уже был
указан явно.

## Что исправлено

В `_groups_for()` (используется и для списка ссылок, и для списка
запасных ссылок) после загрузки групп список `group.links` теперь
явно сортируется по `(position, id)` — так же, как это уже делалось
для ссылок без группы:

```python
for group in groups:
    group.links.sort(key=lambda link: (link.position, link.id))
```

Это чисто отображение — сортировка происходит в Python над уже
загруженным списком объектов, в БД ничего не пишет и не трогает
существующие данные (значения `position`, которые уже могли быть
"перепутаны" предыдущими нажатиями стрелочек, не пересчитываются —
но при этом это не важно, отображение теперь просто уважает
сохранённый порядок как есть).

## Как накатить на VM

```bash
scp app/admin/routes/vless_links.py user@your-vm:/opt/vpn-bot/app/admin/routes/vless_links.py

sudo systemctl restart vpnapi.service
sudo systemctl status vpnapi.service --no-pager
```

Миграций БД не требуется.
