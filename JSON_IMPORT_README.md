# Добавление серверов через JSON-конфиг (админка → Vless-ссылки)

## Что внутри

Замените этими файлами одноимённые в репозитории (пути совпадают со
структурой репо — просто распакуйте архив поверх `botr/`, подтвердив
перезапись):

- `app/admin/config_json_import.py` — **новый файл**.
  Парсер клиентского JSON-конфига Xray/v2rayNG/NekoBox (того, что
  экспортируется целиком — с разделами `inbounds`, `outbounds`, `dns`,
  `routing` и т.д.). Достаёт из `outbounds` все реальные сервера
  (`vless`, `trojan`, `vmess`, `shadowsocks`; служебные `freedom`,
  `blackhole`, `dns` пропускает) и собирает из каждого обычную
  ссылку-шару (`vless://…`, `trojan://…` и т.п.) — с корректными
  `security`/`sni`/`fp`/`pbk`/`sid` для reality, `tls`/`alpn` для tls,
  `serviceName`/`mode` для grpc, `path`/`host` для ws.

- `app/admin/routes/vless_links.py`
  В обработчик `POST /admin/vless-links/new` добавлена вторая ветка:
  если пришло поле `config_json` — ссылка(и) создаются через парсер
  выше (может получиться сразу несколько ссылок из одного конфига,
  например если там balancer из 2-3 серверов); если пришло `url` —
  всё работает как раньше, без изменений.

- `app/admin/templates/vless_link_form.html`
  На форме «Новая ссылка» появился переключатель **Ссылка / JSON-конфиг**.
  Во втором режиме — большое текстовое поле, куда можно вставить весь
  JSON-конфиг целиком, без предварительной обработки руками.

## Как это использовать

1. Открыть `/admin/vless-links` → «Добавить ссылку» (рабочую или запасную).
2. Переключить режим на «JSON-конфиг».
3. Вставить весь экспортированный JSON целиком.
4. Сохранить — админка сама создаст по ссылке на каждый найденный
   сервер. Если серверов несколько, имя каждой ссылке даётся из
   `remarks` конфига + тега (`proxy`, `proxy-2`, …), чтобы они не
   слились в одну запись с одинаковым именем; поле «Название сервера»
   в этом случае игнорируется.

Старый способ (вставить готовую `vless://…`-ссылку одной строкой)
никуда не делся — переключатель по умолчанию стоит на нём.

## Поддерживаемые протоколы и транспорты

- Протоколы: `vless`, `trojan`, `vmess`, `shadowsocks`/`ss`.
- Security: `none`, `tls`, `reality`.
- Транспорты (`streamSettings.network`): `tcp`, `ws`, `grpc`, `h2`/`http`, `kcp`.

Если в конфиге встретится протокол вне этого списка (например
`socks`/`http` — но это инбаунды, их код и не смотрит) — такой
outbound просто пропускается, ошибки не будет, если найдётся хотя бы
один поддерживаемый сервер.

## Как накатить на VM

```bash
# Скопировать файлы (например через scp с локальной машины,
# из корня распакованного архива):
scp app/admin/config_json_import.py     user@your-vm:/path/to/botr/app/admin/config_json_import.py
scp app/admin/routes/vless_links.py     user@your-vm:/path/to/botr/app/admin/routes/vless_links.py
scp app/admin/templates/vless_link_form.html user@your-vm:/path/to/botr/app/admin/templates/vless_link_form.html

# Перезапустить контейнер с админкой/API (bot трогать не нужно —
# изменения только в админ-панели):
docker compose restart api
```

Миграций БД не требуется — таблицы `vless_links`/`vless_link_groups`
не менялись, только способ добавления записи в них через форму.
