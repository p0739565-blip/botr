# Скриншоты от админов в тикетах поддержки

## Было раньше

Пользователи уже могли слать боту скриншоты/видео в обращение —
`app.services.support.add_user_message` это умела, и админка их уже
показывала в истории переписки. А вот в обратную сторону — из админки
пользователю — можно было отправить только текст:
`reply_to_ticket` принимал один обязательный `text`, вложений не было
вообще.

## Что добавлено

- **Форма ответа** (`support_detail.html`) — новое поле "Прикрепить
  скриншот" (файл), текст теперь необязателен — можно отправить только
  картинку, только текст, или и то и другое вместе.
- **`reply_to_ticket`** (`app/admin/routes/support.py`) — принимает
  файл, проверяет что это реально изображение (`content_type` должен
  начинаться с `image/`) и что он не больше 10 МБ (тот же практический
  потолок, что у Telegram Bot API для фото), сохраняет как
  `SupportAttachment` (та же таблица, что и для вложений от
  пользователя — история переписки отображает их уже сейчас, менять
  вёрстку истории не пришлось), и отправляет пользователю через
  `bot.send_photo()` с текстом ответа в подписи (если текст был).
- Если отправить в Telegram не получится (пользователь заблокировал
  бота и т.п.) — ответ и скриншот всё равно останутся сохранены в
  истории обращения, ровно как уже было устроено для текстовых
  ответов раньше — просто увидите баннер "не удалось отправить".

## Файлы

- `app/admin/routes/support.py` — изменена только `reply_to_ticket`,
  остальные функции файла (список тикетов, закрыть/переоткрыть/
  удалить/очистка) не тронуты.
- `app/admin/templates/support_detail.html` — только форма ответа,
  остальное без изменений.

## Как накатить

```bash
scp app/admin/routes/support.py         user@your-vm:/opt/vpn-bot/app/admin/routes/support.py
scp app/admin/templates/support_detail.html user@your-vm:/opt/vpn-bot/app/admin/templates/support_detail.html

sudo systemctl restart vpnapi.service
sudo systemctl status vpnapi.service --no-pager
```

Бот не трогаем — файл отправляется тем же одноразовым `Bot()`, что уже
использовался для текстовых ответов, живёт в процессе `vpnapi.service`.
