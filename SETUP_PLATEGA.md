# Подключение оплаты картой через Platega

Интеграция добавляет реальную оплату картой (кнопка «💳 Банковская
карта» в боте) через платёжный шлюз [Platega](https://docs.platega.io/).
До этого была заглушка «Оплата картой скоро будет добавлена».

## Как это работает

1. Пользователь жмёт «Банковская карта» → выбирает тариф.
2. Бот создаёт транзакцию в Platega (`POST /transaction/process`) и
   сразу заводит запись `PlategaPayment` в своей БД (статус `PENDING`),
   чтобы потом сопоставить callback с пользователем и тарифом — сам
   Platega не возвращает наш payload в вебхуке, только `id` транзакции.
3. Пользователю приходит кнопка со ссылкой на страницу оплаты Platega.
4. После оплаты Platega шлёт **вебхук** на ваш сервер
   (`POST /webhooks/platega`) со статусом транзакции.
5. Вебхук проверяет заголовки `X-MerchantId`/`X-Secret`, помечает
   платёж как `CONFIRMED`, начисляет подписку и отправляет
   пользователю сообщение с QR-кодом — точно так же, как при оплате
   Stars, только без диалога в боте (бот и API — разные процессы,
   поэтому вебхук создаёт свой `Bot()` и шлёт сообщение напрямую по
   `chat_id`).

Реальная выдача подписки происходит **только по вебхуку**, не по
редиректу пользователя на `return`-страницу — редирект ненадёжен
(пользователь может закрыть вкладку раньше).

## Шаг 1. Файлы

Распакуйте архив `platega_integration_files.zip` поверх репозитория
(структура путей внутри архива совпадает с репозиторием) — это создаст
2 новых файла и изменит 7 существующих:

**Новые файлы:**
- `app/services/platega.py` — HTTP-клиент Platega API
- `app/webhooks/__init__.py`
- `app/webhooks/platega.py` — обработчик вебхука

**Изменённые файлы:**
- `app/config.py` — добавлены `PLATEGA_MERCHANT_ID`, `PLATEGA_SECRET`,
  `PLATEGA_BASE_URL`, `PLATEGA_CARD_METHOD`
- `app/models.py` — добавлена модель `PlategaPayment`
- `app/api.py` — подключён роутер вебхука + страницы
  `/payments/platega/return` и `/payments/platega/failed`
- `app/services/payments.py` — вместо заглушки `build_card_invoice()`
  теперь `create_card_payment()`, реально создающий транзакцию
- `app/services/subscription.py` — добавлена
  `send_subscription_by_chat_id()` для выдачи подписки из вебхука
- `app/handlers/payment.py` — кнопка «Банковская карта» теперь
  реально работает

Альтернатива — применить `platega_integration.patch`:

```bash
cd /path/to/botik
git apply /path/to/platega_integration.patch
```

(если `git apply` ругается на несуществующие файлы — значит ваша
рабочая копия разошлась с тем состоянием репозитория, из которого я
брал код; в этом случае проще руками скопировать файлы из архива)

## Шаг 2. Получить доступы Platega

В личном кабинете Platega, на странице «Настройки», возьмите:
- `MerchantId`
- API-ключ (`Secret`)

Также уточните у вашего менеджера Platega, **подключён ли картный
каскад** на вашем мерчанте. Если нет — при первой попытке оплаты вы
увидите в логах `400 "No available card cascades"`. В этом случае
попросите менеджера подключить карту, либо временно переключитесь на
СБП (см. `PLATEGA_CARD_METHOD` ниже — правда, это уже не совсем
«банковская карта» по смыслу кнопки).

## Шаг 3. Добавить переменные в `.env`

```env
PLATEGA_MERCHANT_ID=ваш_merchant_id
PLATEGA_SECRET=ваш_api_key

# Не обязательно, значения по умолчанию:
# PLATEGA_BASE_URL=https://app.platega.io
# PLATEGA_CARD_METHOD=11
```

**Без этих двух переменных бот и API не запустятся** — `config.py`
требует их так же строго, как `BOT_TOKEN` и `CHANNEL_ID`.

## Шаг 4. Указать Callback URL в Platega

В личном кабинете Platega: **Настройки → Callback URLs**, укажите:

```
https://<ваш SUB_DOMAIN>/webhooks/platega
```

(тот же домен, что уже используется для `/sub/<token>` — переменная
`SUB_DOMAIN` в вашем `.env`).

Проверьте, что этот URL доступен снаружи без авторизации на уровне
Nginx (т.е. не защищён Basic Auth и т.п.) — иначе Platega не сможет
достучаться и не будет знать, что оплата прошла.

## Шаг 5. Пересобрать и перезапустить

```bash
docker compose up -d --build
```

Это создаст новую таблицу `platega_payments` в БД автоматически (через
`init_models()` при старте — как и остальные таблицы, без Alembic).

## Шаг 6. Проверить

1. В боте: «💳 Купить подписку» → «Банковская карта» → выбрать тариф.
2. Должна прийти ссылка на оплату.
3. Оплатите тестовым способом (или дождитесь фейкового callback'а —
   в ЛК Platega есть кнопка отправки тестового callback'а после
   создания транзакции: раздел docs.platega.io → «CallBack для
   тестирования платежей»).
4. Проверьте логи API-процесса:
   ```bash
   docker compose logs -f api
   ```
   При успешной обработке никаких warning/error про
   `platega_webhook` быть не должно.
5. Подписка и QR-код должны прийти в чат с ботом автоматически, без
   каких-либо действий в самом боте.

## Что ещё не сделано (сознательно, для следующего шага)

- **Возвраты/чарджбэки** — при статусе `CHARGEBACKED` вебхук сейчас
  только помечает запись `PlategaPayment`, но НЕ отзывает уже выданную
  подписку автоматически (чтобы не рвать доступ на автомате при
  спорных возвратах). Отзыв — вручную через админку, там уже есть
  функция revoke.
- **Сверка зависших PENDING** — если callback вообще не дошёл (сеть
  моргнула на стороне Platega дольше, чем 3 ретрая), деньги спишутся,
  а подписка не выдастся. `app/services/platega.py` уже содержит
  `get_transaction_status()` для ручной/периодической сверки — сейчас
  им никто не пользуется, стоит повесить на cron аналогично
  `xray_sync.py`.
