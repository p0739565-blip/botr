# VPN Bot MVP

Минимальный функционал:
- Пользователь заходит в бота → бот проверяет подписку на Telegram-канал
- Если подписан — создаётся подписка на VPN на 7 дней (токен + запись в БД)
- Бот присылает ссылку на подписку и QR-код
- Ссылка ведёт на FastAPI-эндпоинт (`/sub/<token>`), который отдаёт список
  конфигов (vless/hy2) в том же формате, что и старый Cloudflare Worker —
  клиентские приложения (v2rayN, Happ, Hiddify и т.д.) понимают её напрямую

## Структура

```
vpn-bot/
├── docker-compose.yml       # postgres + bot + api
├── .env.example              # переменные окружения (скопировать в .env)
├── requirements.txt
└── app/
    ├── config.py              # чтение .env
    ├── db.py                  # SQLAlchemy async engine/session
    ├── models.py              # User, Subscription
    ├── vless_links.py         # статический список ваших VPN-конфигов
    ├── bot.py                 # aiogram-бот (long polling)
    └── api.py                 # FastAPI, отдаёт /sub/<token>
```

## Как это работает

1. `app/vless_links.py` — сюда переносите ваши реальные vless/hy2-ссылки
   (то, что раньше лежало в `vlessLinks` в worker.js). Ссылки статичны и
   одинаковы для всех — так же, как было у вас: разграничение доступа идёт
   не через отдельный uuid в самой ссылке, а через ваш `token` в URL
   подписки и проверку срока действия в БД.
2. Бот при `/start`:
   - проверяет через Bot API, состоит ли пользователь в канале
     (`bot.get_chat_member`)
   - если да — создаёт (или продлевает) запись в `subscriptions` с
     `expiry = now + 7 дней` и случайным токеном
   - формирует URL вида `https://ваш-домен/sub/<token>` и присылает
     ссылку + QR-код
3. FastAPI-эндпоинт `/sub/<token>`:
   - если токена нет в БД или подписка истекла — отдаёт пустой список
     (как `emptyResponse` в вашем воркере)
   - если действует — отдаёт полный список конфигов с заголовками
     `#profile-title`, `#subscription-userinfo` и т.д.
   - сохранена простая проверка User-Agent: браузерам — 404,
     VPN-клиентам — подписка (антибраузерную decoy-страницу из вашего
     воркера можно перенести отдельным шагом, для MVP она вынесена)

## Запуск

1. Скопируйте `.env.example` → `.env`, заполните `BOT_TOKEN`,
   `CHANNEL_ID`/`CHANNEL_USERNAME`, `SUB_DOMAIN`, `POSTGRES_*`.
2. Впишите свои реальные ссылки в `app/vless_links.py`.
3. `docker compose up -d --build`
4. Настройте Nginx + TLS (например certbot) на VM так, чтобы
   `SUB_DOMAIN` проксировался на контейнер `api` (порт 8000 внутри сети,
   пробросьте наружу как вам удобно).

## Персональные uuid и лимит устройств (обновление)

Раньше все пользователи получали один и тот же uuid в конфиге — это не
позволяло серверу отличать пользователей друг от друга. Теперь:

- у каждого `User` в БД есть свой `vless_uuid` (генерируется при первом
  `/start`)
- `Subscription.device_limit` — сколько устройств разрешено на этой
  подписке (2-10, задаётся тарифом)
- `Device` — таблица с IP-адресами, которые сервер увидел для этого
  пользователя

### Как это работает на VM

1. **xray** должен быть настроен так, чтобы у каждого клиента в inbound
   был `email` = его uuid, и включён access-лог с `loglevel: info`:
   ```json
   "log": { "access": "/var/log/xray/access.log", "loglevel": "info" }
   ```
2. **`app/xray_sync.py`** — пересобирает список `clients` в конфиге xray
   из БД (только активные подписки) и делает `systemctl reload xray`.
   Вызывается автоматически ботом после выдачи подписки, плюс имеет
   смысл повесить на cron каждые несколько минут — чтобы вовремя убирать
   истёкшие подписки, даже если бот в этот момент ничего не выдавал:
   ```bash
   */5 * * * * cd /path/to/vpn-bot && /path/to/venv/bin/python -m app.xray_sync
   ```
3. **`app/device_guard.py`** — постоянно работающий демон (systemd,
   от root — нужны права на iptables), который следит за access-логом
   xray в реальном времени. Как только на uuid появляется IP сверх
   `device_limit`, самый старый по активности IP получает
   `iptables -I INPUT -s <ip> -j DROP` на `DEVICE_BAN_SECONDS`.

   Важно: это подсчёт по **уникальным IP**, не по "настоящим" устройствам
   — см. ограничения этого подхода в тексте выше по переписке. Формат
   строки лога у разных версий xray может отличаться — перед боевым
   запуском проверьте реальный `access.log` и при необходимости
   поправьте `LOG_LINE_RE` в `device_guard.py`.

   Пример unit-файла (`/etc/systemd/system/device-guard.service`):
   ```ini
   [Unit]
   Description=VPN device guard
   After=network.target xray.service

   [Service]
   WorkingDirectory=/path/to/vpn-bot
   ExecStart=/path/to/venv/bin/python -m app.device_guard
   Restart=always
   User=root

   [Install]
   WantedBy=multi-user.target
   ```
